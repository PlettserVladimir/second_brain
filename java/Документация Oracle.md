# Руководство по миграции на JDK 25

Это руководство поможет вам перенести существующие приложения с более ранних версий Java на JDK 25. Основное внимание уделяется обратно совместимым изменениям, удалённым API и новым функциям, которые могут повлиять на поведение вашего кода.

## Ключевые области проверки

### 1. Языковые изменения
- **JEP 512 (Compact Source Files)** – теперь можно писать `void main()` без класса. Это не ломает старый код.
- **JEP 513 (Flexible Constructor Bodies)** – разрешён код до `super()`, что может изменить порядок инициализации, если вы полагались на старый порядок.
- **JEP 507 (Primitive types in patterns)** – это preview, требует `--enable-preview`. Если вы использовали pattern matching для объектов, проверьте, не появились ли конфликты с новыми примитивными паттернами.

### 2. Библиотеки и API
- **Scoped Values** – новая альтернатива `ThreadLocal`. Если вы активно используете `ThreadLocal`, рассмотрите возможность перехода для улучшения производительности в виртуальных потоках.
- **Удалённые или устаревшие API** – проверьте Release Notes на предмет удалённых методов. В JDK 25 удалена поддержка 32-битной x86 платформы (JEP 505).
- **Структурированный параллелизм** – новый API в `java.util.concurrent`. Если вы используете `ExecutorService` для параллельных запросов, подумайте о рефакторинге.

### 3. JVM и производительность
- **Компактные заголовки объектов (JEP 519)** – уменьшают потребление памяти, но могут повлиять на инструменты, анализирующие дампы кучи.
- **Упреждающее профилирование** – может изменить время запуска. Проверьте, не появились ли артефакты в логировании.

### 4. Безопасность
- **Новые API (JEP 470, JEP 510)** – не ломают обратную совместимость, но рекомендуются к использованию вместо устаревших методов вывода ключей.

### 5. Инструменты
- **jpackage** – улучшена поддержка создания установщиков. Если вы использовали сторонние утилиты, рассмотрите переход на встроенный инструмент.

## Шаги миграции

1. **Изучите Release Notes** – полный список изменений.
2. **Протестируйте с JDK 25 в изолированной среде** – запустите все модульные и интеграционные тесты.
3. **Проверьте зависимости** – убедитесь, что используемые сторонние библиотеки совместимы с JDK 25.
4. **Настройте флаги JVM** – при необходимости добавьте `--enable-preview` для preview-функций.
5. **Мониторьте производительность** – сравните метрики до и после миграции.

## Известные проблемы и обходные пути

- Если ваш код использует рефлексию для доступа к закрытым полям, обратите внимание на изменения в инкапсуляции модулей (может потребоваться открытие пакетов).
- Для приложений с большим количеством виртуальных потоков проверьте настройки пула потоков.
